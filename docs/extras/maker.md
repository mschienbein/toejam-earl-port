# Maker: designed courses, local editor and self-contained share codes

Status: native-size first-phase implementation, 2026-10-25. See [the executable format and loader specification](maker-format.md) for exact fields, local CLI/share-code authoring, capability admission and the native 19×26/one-or-two-seat profile. This document retains the broader editor/generalized-capacity design. Maker is opt-in, not a new default generator or a shipped set of extracted levels. Hosted sharing, accounts, spending and HD art remain out of scope.

`G` is the [matching decompilation](https://github.com/mschienbein/toejam-earl-decomp), researched at commit `57fc83fc54781af8e992bbc3b32afe788c1dbd01`; `G/...` paths are relative to it, and `P/...` paths are relative to this repository. REV 02 addresses come from `G/config/rev02/names.json`.

## Course format: explicit, bounded, asset-free

Primary editable file: UTF-8 `.tjemaker.json`, schema `tje-maker/1`. Strict fixed schema, unknown fields/duplicate keys rejected, no scripts/expressions, floats, paths, URLs, executable pointers or arbitrary byte attachments. Limits are checked before allocating arrays. Course files contain **newly authored arrangements and logical references**, never decoded graphics, palettes, text, audio, ROM tables, snapshots or a copy of the original fixed maps.

| Field / type | Meaning and bounds |
| --- | --- |
| `schema` | Exact `tje-maker/1`; unsupported major versions fail clearly. No heuristic repair or silent migration. |
| `catalog` | Versioned logical asset/behavior catalog, initially `tje91-rev02/1` or `tje91-rev00/1`. Catalog metadata records symbols/indices and semantic capability names; payloads resolve from the importing user's ROM. Revision compatibility is explicitly tested before a shared catalog ID can be introduced; do not assume both revisions are interchangeable. |
| `title`, `author`, `description` | Newly authored UTF-8 strings, respectively at most 128, 64 and 1024 bytes, displayed as text not markup. No usernames/accounts are required. Reject control characters except permitted description line breaks. |
| `runtime_seed` | Exactly sixteen lowercase hexadecimal digits encoding u64, avoiding JavaScript integer precision loss. Drives AI/present wrapping, not layout generation. Streams derive from seed + ruleset + stable level/object ID + purpose, using the versioned derivation/PRNG in the larger-level design. |
| `rules` | Named enhanced ruleset version; allowed hero count 1–4; co-op or Overlord capability flag; fixed optional tick limit, initial lives/resources and inventory/present-identification policy. Finite enums and bounded integers only; no arbitrary stat scripts. A course cannot silently enable a user's disabled extra or replace local controls. |
| `start` | Starting LevelId and four explicit safe spawn-point references (unused seats may share a point only if deterministic nonoverlapping placement offsets are validated). |
| `finish` | `reach_exit` or `collect_and_exit`; stable exit reference and optional finite required collectible-ID list. Completion is a transaction, not a ROM PC or assumption that level 26 always ends this course. |
| `levels` | 1–32 unique u16 LevelIds, canonical order by ID; no significance attached to array index or original story floor number. Each has size 8–64 columns/rows, an environment/music logical reference, cells, spawn points, object placements, transition links and optional path triggers. |
| `cells` | Row-major run-length pairs `[count, cell]`, count positive, total exactly width×height. Canonical encoder merges adjacent identical cells. `cell` is u16: bits 0–6 base metatile ID (0–121), bit 7 base mirror, bits 8–11 overlay ID (0 means none, otherwise 1–15), bit 12 overlay mirror (zero when no overlay); bits 13–15 must be zero. These are references to the local ROM catalog, **not** copied lookup-bank payloads. Generation class/visit/region flags cannot enter this field. |
| `spawn_points` | Unique level-local u32 IDs, integer world-pixel positions snapped to eight pixels and legal support/clearance for supported archetypes; references validated before loading. Coordinates use the `(128,64)` first-cell origin and border convention in the larger-level design. |
| `objects` | Unique course-wide u32 IDs. Tagged types: `earthling`, `item`, `service`, `ship_piece`, `telephone`, `elevator`, `exit`. Each supplies logical definition reference and integer position. Earthlings additionally permit `awake`/`asleep` only where catalog capability allows; items specify exact identity (appearance can follow course wrapping policy). No raw original state numbers, health-visibility bytes, draw flags, callback pointers or renderer handles. |
| `links` | Elevator/exit endpoint IDs and destination LevelId/spawn-point ID; explicit one-way/two-way semantics. Every nonterminal endpoint resolves. Finish exits are explicit. No hidden `level+1`. |
| `fall_target` | Another level/spawn-point reference, or `lose_life_and_respawn` at a named checkpoint. Cycles are allowed only when all destinations resolve and have safe landing; no accidental negative-level wrap. |
| `paths` | Optional newly authored collapsing-path groups: stable ID, cell-coordinate list, reciprocal cardinal direction mask per listed cell, `step_on` trigger, bounded arming/delay ticks and replacement base/overlay reference. Validate source/replacement terrain and duplicate ownership. This is a finite mechanism, not the original recursive generation scratch or an arbitrary event language. |

Level actor caps align with the larger-level profile: at most 64 Earthlings (services/ship-piece actors included), 128 items, 64 non-Earthling prop/transition objects and sixteen spawn points per level. Max course-wide static object records 8192; IDs are unique even after an object is collected. Additional Overlord director-spawned bodies/traps obey that ruleset's tighter dynamic caps. A 1024-entry enhanced runtime arena, separate mandatory-object reservations and 4 MiB authoritative sidecar budget cover at most four hero-active floors; a validator computes actual pool/companion requirements rather than assuming every static object is a one-piece sprite.

The aggregate 2 MiB canonical-body limit also applies: per-field maxima are not a promise that every maximum-sized grid and object list fits simultaneously. The editor shows the encoded-size budget before play/export and rejects oversized playable documents without losing the editable draft.

The initial catalog exposes the existing two archetypes and all existing content kinds/presents through safe semantic capabilities. It does not promise arbitrary combinations that violate a kind's terrain or service contract. New artwork, custom music/sample uploads, arbitrary imported image tiles and user scripts are intentionally out of scope. Four-player characters use the existing runtime ROM-derived palette variants, not assets stored in a course.

## Loading replaces generation end to end

A `DesignedV1` level source is an immutable, validated course model. On entry:

1. Check schema/catalog/ruleset/player count/disabled-feature compatibility and course digest before any engine/world mutation. Resolve definition IDs from the user's already-imported supported ROM; a missing resource is an error, not a fake blank tile or fallback stock level.
2. Construct candidate geometry/path/anchor state and persistent objects at their **authored positions**. Validate bounds, actual per-eight-pixel terrain, object footprints, legal sleeping/initial states, required capacity, links, safe arrivals/falls/checkpoints and finish references. Do not invoke random actor/item placement to repair a mistake.
3. Publish the candidate level transactionally at the enhanced loading boundary. Initialize only permitted runtime randomness (AI, wrapping) from explicit streams; no implicit `GenerateLevelSeeds`, original `LevelEarthlingChoices`, item-count generator, ship-level assignment or level-1 fixed-position injection.
4. Play through the shared enhanced player/entity/movement/contact/elevator/item code. Mutations/collectible removal/path collapse are runtime deltas by stable ID. Revisit and restore reuse those deltas, not a freshly populated level. Preserve one mutable instance per LevelId shared by all heroes.
5. Finish/failed-run presentation is a mode-owned nonblocking state; do not require original final-level number/ending globals to claim completion. A course may use existing scene resources only through separately supported transition capabilities, never an arbitrary original scene address.

### Override roots

Use EnhancedMode's separate opt-in `EnhancedProfile(name, &[Translation], &[FramedTranslation])` and physical `Context` ABI, not faithful selection tables. Selected nested calls stay selected, other bounded calls run compiled originals; Atomic/Functional callbacks have a synthetic RTS charge and **no** exact-time/source-proof authority. The dispatch precedent is the opt-in `NativeCompiledOriginalCallees` profile ([P `docs/ENGINE.md:437–506`](docs/ENGINE.md#L437)). The first registry has no sidecar/editor/draw API and is not enough by itself.

Required selected ownership boundaries:

- `GenerateLevelSeeds`, `MapLoadPlayerLevel`, `ChangeLevel`, final/special map loading and original map-copy/swap helpers: route exclusively to `DesignedV1` under this profile. Canonical cells never pass through original region/alternative generation after authored loading.
- `SetupInitialEarthlings`/`EarthlingRetainLevelBank`/release/load and `SetupInitialInventory`/`LoadLevelItemBank`/release/population helpers, ship assignment and elevator setup: use explicit authored records and stable-ID state. Inventories initialize from the course rules, not accidental original two-player setup.
- `GetMapTerrainAtWorldPosition`, `UpdateLandAroundPlayer`, terrain placement/collision/movement bounds, path changes and falls; exploration/discovery and map/ship/elevator markers: use the dynamic bounded geometry and links. Original two-bank and fixed-stride leaves cannot remain downstream of this ownership change.
- Co-op player/present/contact/effect/elevator/ship progression closure and host world/HUD/map rendering: explicit hero count/roles, new finish semantics, nonblocking transitions and safe catalog capability dispatch. Do not pass host IDs/pointers to original RAM object ABIs.

Keep faithful device/audio/compiled-original infrastructure and safe ROM resource/math/sound leaves; validate the complete callback closure before starting. The shared future typed sidecar/context, frame/phase bridge, generalized actor/capacity and renderer work is prerequisite. Maker can start with one/two seats; its data/loader must still honor the declared 1–4 range only once the four-player closure is present. Unsupported course capabilities fail admission, not half-load a course with missing heroes.

## Local editor workflow

Implement a local editor using native winit/egui/wgpu and a browser canvas/DOM counterpart over the **same** bounded course model/codec/validator. No local HTTP service, hosted account or implicit upload is necessary. Browser files use explicit file picker/download and optional IndexedDB drafts; native files use user-chosen paths and atomic replacement. Never interpret a course field as a filesystem path.

- New course creates a newly authored blank/safe template in host code, not extracted level 1. Default safe floor can be composed interactively from catalog references; any shipped example must be newly authored and contain no stock map transcription.
- Palette browser decodes metatile thumbnails/overlay previews/actor icons from the user's ROM at runtime, including flips and terrain overlays. New authored text/controls can use existing project UI fonts. No thumbnails or extracted palettes are committed to P or packaged into the document/code.
- Tools: paint/erase/fill/rectangle, base/overlay mirror, terrain-property overlay, place/move/delete actors/items/services, arrival/exit/spawn points, link endpoints, fall destination and collapsing-path group editor; grid/zoom/pan, selection copy within the authored document and undo/redo. Selection copy copies references/placements, not images.
- Use inverse editor commands/diffs and coalesce a drag stroke. Bound undo history (e.g. 256 commands / 64 MiB) and draft/file sizes. Do not copy the entire engine or every level per pointer movement. Editor camera/selection/undo are local authoring state, not game simulation state.
- Inspector shows cell/reference, actual tile terrain, footprint/safe-zone conflicts, static object/pool and encoded-size budgets, links and metadata. Errors point at exact coordinates/object IDs. Invalid work can be saved as an editor draft, but cannot be admitted to play or exported as a playable share code.
- Playtest freezes an immutable document/digest and starts a new enhanced session using its seed/ruleset and selected one/four pads. Stop preview discards runtime deltas and returns to the untouched editable model. Authoring edits during a preview mark the next run dirty; they never change a live rollback/snapshot world.
- Native/browser playtest and file import/export are all in the phased estimate. Keyboard/pad gameplay bindings remain personal settings; editor shortcuts/pointer capture do not leak actions into the game. Four-player preview uses co-op's 2×2 400×224 logical views; single-player uses the ExtendedView 400×224 envelope. Editor zoom-out can show the whole course without revealing that information during gameplay.

Hard safety validation rejects malformed data, impossible capacities, unresolved references, unsafe mandatory arrivals and illegal footprints. A separate reachability analyzer builds a tile-terrain graph for each supported archetype and checks required paths/collectibles/exit under declared mobility assumptions. It flags power-dependent routes and destructive paths; it cannot prove every dynamic enemy/present puzzle solvable. A deterministic recorded successful playtest can attach a local **clear stamp** bound to the course/ruleset digest. The stamp is advisory, not a trusted anti-cheat certificate or prerequisite for saving work; unverified courses show that status. Do not claim that a flood fill proves a full playthrough.

## Share codes without a server

A code is the **course itself**, not a short hosted lookup token:

`TJM1:` followed by unpadded Base64URL of a fixed header and zlib-compressed canonical JSON body. Body is the exact playable authored schema above, not engine state, editor undo/cache or a ROM-generated map export.

Header specification: four-byte ASCII `TJMC`; u16 little-endian major schema (1); u16 little-endian codec flags (1 = zlib/RFC1950 DEFLATE; other bits rejected); u32 little-endian uncompressed length; u32 little-endian compressed length; 32-byte SHA-256 of canonical **uncompressed** JSON; then precisely the declared compressed bytes, with no trailing stream/data. Canonical JSON uses RFC 8785 string/key ordering rules, integers only, sorted ID-bearing arrays, normalized cell RLE and the fixed sixteen-character seed representation. Different valid compression implementations may emit different codes for the same digest; identity is the canonical body digest, not compressed bytes.

Limits before/deep inside parsing: text ≤3 MiB; compressed and uncompressed bytes each ≤2 MiB; exact declared lengths; decompression stops at the bound even if a header lies; bounded JSON nesting (sixteen), string lengths, array counts, cell totals and all semantic caps above. Reject duplicate keys, invalid UTF-8, out-of-range numbers, unknown enum/capability/catalog, bad digest and extra payload. Never evaluate markup, fetch a URL, unpack an archive, execute a script or import embedded binary art. SHA-256 detects corruption/identity; it authenticates **neither author nor safety**.

Tiny RLE courses may produce convenient pasteable codes; elaborate maximum-size courses can be hundreds of KiB or more. Warn above 8 KiB and offer a local file instead, but do not truncate or silently upload the payload. A human-sized short code for an arbitrary large level is impossible without an external content store or manual shared catalog; do not invent a free server to hide that constraint. Copy/paste, local files and explicit user-controlled P2P transfer are sufficient.

### ROM-derived content boundary

A newly authored arrangement of logical references is shareable without supplying the art. Resolving it requires the recipient's supported ROM. Original fixed maps, ROM table dumps, extracted palette/tile data and captured snapshots are **not** made shareable merely by compressing them. Initial Maker intentionally has no automatic "export original generated/fixed map" command. A future private import must carry provenance restrictions; it is not included here. Public fixtures use newly authored/synthetic metadata/arrangements and contain no original map, dialogue, tile/color/sample data. Keep decoded previews and core snapshots in private user storage.

Core snapshot format 1 (`TJESTATE`) contains ROM SHA1, frame, canonical CPU and full device/timing/input/audio state, but no enhanced identity/sidecar. Designed-game saves wrap it transactionally with profile/body-manifest/ruleset/catalog/course digest, immutable course identity and all player/map/object/RNG/runtime deltas; reject cross-course/profile restore before mutation. The embedded core payload remains private ROM-derived data and is never a share code. Enhanced input recordings/netplay require the same manifest, course digest and ownership checks. The current two-seat recording/rollback schemas are not silently repurposed.

## Hosted sharing: needs explicit later approval

No implementation or network calls for this are proposed now. A future hosted service would need content-addressed course storage, upload/browse API and durable database/object storage; identity/account or anonymous-abuse policy; rate limits/quotas, moderation/report/takedown and rights policy; proof/clear-stamp trust model, compatibility search, backups, privacy/retention/security operations and funding/hosting ownership. User approval is required before accounts, service deployment or spending. Upload only validated authored course data, never ROMs, extracted graphics/audio, core saves or private identity/controller information. Public short links depend on this service and are not promised by the local format. No TURN relay or hosted game server is implied.

## Balance, tests, risks and phase sizes

Balance is course-owned and explicit: player-count range, original archetype stats, item/resource supply, permitted present mechanics, environment, hostile count/composition/spacing, safe arrivals/checkpoints, collapsing paths and goal/timer. Density/cap validation prevents hostile clusters from making arrival unavoidable damage. A course may be difficult or intentionally puzzle-like, but cannot override character HP/collision via script or hide a changed ruleset. Runtime palette swaps are per-instance transforms of the user's ROM palettes, never four replacement CRAM banks or course attachments.

Estimates [INFERENCE], engineering days after shared sidecar/phase/render and dynamic geometry/query/actor capacity foundations. Maker replaces generation and does **not** require the expanded random generator itself. Full four-player courses additionally require the co-op closure; Overlord-tagged courses require its complete ruleset.

Acceptance tests required before shipping:

1. Existing REV 00/REV 02 faithful engine session corpus remains identical in native/browser frame **and audio hashes** with Maker absent/off. Opening/closing the editor must not mutate an ongoing faithful session or select an enhanced profile implicitly.
2. Newly authored single-level, multi-level, four-seat and Overlord-capability courses round trip through JSON, canonical digest, share code and local file on native/browser; ordering and compression differences preserve semantic identity. Wrong schema/catalog/course/profile/ROM restore fails before state mutation.
3. Property/fuzz parser and import tests: malformed Base64, false lengths, deflate bombs, huge counts, invalid UTF-8/control text, duplicate keys/IDs, unknown fields, bad cell sums/bits/overlays, missing links/goals, integer boundaries, capacity/companion overflow and trailing streams. No OOM, filesystem escape, external fetch or partial publication.
4. Runtime exact placement of every supported content kind/present/service and both character archetypes on all legal terrains, with mirrored base/overlays. No implicit original generator/level-1 actor/ship-part insertion. Invalid footprints cannot be silently relocated.
5. Explicit one-way/two-way travel, four heroes on different floors, all fall/checkpoint outcomes, path destruction, eliminated/rejoining hero, simultaneous part/item/exit transactions and complete finish/failure. Revisit/snapshot/restore retains IDs/deltas; layout never regenerates itself from an unrelated seed.
6. Editor paint/fill/mirror/link/undo/redo/save/open and crash-recoverable local drafts; all semantic changes create a new digest. Preview/stop does not alter the document, and authoring controls cannot enter live gameplay input. Revoking browser file/storage permission returns an actionable error without losing the model.
7. Native/wasm same course/rules/seed/input gives identical authoritative/core/audio hashes; snapshot mid-path/transition/AI timer and resimulate. Camera scale/layout/presentation refresh/cache eviction never changes activity/RNG/goal. Four-pad and reconnection tests use the enhanced schema, not original two-pad assumptions.
8. Max 64×64 cells/32 levels, object/arena/draft/code caps, dense four-view maps beyond VDP limits and renderer-cache pressure; no skipped collisions or missing mandatory resources. Reachability analyzer marks capability-dependent puzzles and clear stamps bind exactly to digest/rules.
9. Public audit and fixture review prove there are no stock level transcriptions, ROM-derived text/tables/palettes/graphics/audio/cache/save attachments. A share code is not a legal/technical bypass for extracted assets; opening a code never hosts or uploads anything.

Principal risks: schema becoming an unsafe scripting language; authored path/terrain combinations that break traversal; accidental original bank/generation fallthrough; assuming a local clear stamp proves anti-cheat; unwieldy large codes; two UI implementations diverging. Strict data/capabilities, one shared codec/validator, immutable playtest documents and honest file-size UX are the boring recommended design.

The first phase implements bounded format/codec/validation, three newly authored data courses and an enhanced native-size terrain-and-population loader. The graphical editor and generalized geometry/actor/four-seat/Overlord closures remain later phases; unsupported capabilities fail admission before mutation rather than selecting a partial implementation. See [maker-format.md](maker-format.md) and the private MakerFormat report for exercised gates and evidence; no ROM-derived map/assets/saves are public course fixtures.
